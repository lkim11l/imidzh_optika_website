## Настройки после подключения

Использовать отдельную ветку с подготовленным сервером `server/timeweb.mjs`. Текущая основная ветка ещё не содержит этих изменений: автоматический запуск её обычной команды `npm start` использует сервер предварительного просмотра.

- Тип: backend Node.js 22 либо Docker с Node.js 22.
- Сборка: `npm ci && npm run build:timeweb`.
- Запуск: `npm run start:timeweb`.
- Директория проекта: корень репозитория.
- Проверка состояния: `/healthz` (проверяет процесс, не базу).
- Переменные: `HOST=0.0.0.0`, `PORT=4173`, `STAGING=true`, `NODE_ENV=production`.
- `SUPABASE_URL` и `SUPABASE_PUBLISHABLE_KEY`: адрес российского тестового экземпляра и только публичный ключ. Секретный/service-role ключ в браузерную конфигурацию запрещён.
- Проверить выбранный порт в настройке веб-сервера платформы.
- Российский регион. Бесплатный технический HTTPS-домен; optikim.ru пока не подключать.

## Ограничения и стоимость

Цена «от 1 ₽» относится к тарифам фронтенда; её нельзя считать ценой всей системы. Текущая документация указывает 0,000495 ₽ за входящий HTTP-запрос (4,95 ₽ за 10 000), включая картинки, стили и скрипты, 2 ГБ диска. Можно установить лимит запросов; при достижении лимита или недостатке баланса приложение останавливается. У сайта есть серверные SEO-страницы и обработчик изображений. Backend в App Platform разворачивается на отдельном облачном сервере; цену нужно подтвердить в форме перед заказом.

Управляемый PostgreSQL сам по себе не заменяет Supabase: текущему сайту нужны также Auth, REST/RPC, RLS, Storage и функция отправки почты. Не подставлять обычный PostgreSQL вместо SUPABASE_URL. Сначала выбрать и оценить российское размещение этих сервисов либо отдельно подготовить замену программного интерфейса.

До публичных тестов подготовить отдельную базу без реальных заявок и выключить отправку почты. На тестовой копии формы не должны писать в действующую зарубежную базу. Существующий сервер намеренно отказывается запускаться с адресом `.supabase.co`.

После развёртывания проверить все URL из baseline-urls.json, каталог, товары, фото, авторизацию, права админки, тестовую заявку, SMTP и сохранение данных после повторного деплоя. DNS менять только после успешной проверки и согласования полной стоимости.
