# Уведомления о заявках на email

Подготовлен код. Пока миграция, Edge Function, секреты и расписание не подключены в Supabase, письма не отправляются. Существующая форма записи и панель заявок работают как раньше.

## Вариант без доступа к домену: почта Mail / inbox.ru

1. Владелец ящика создаёт **пароль для внешнего приложения** в настройках безопасности Почты Mail. Обычный пароль от почты не нужен. Инструкция: https://help.mail.ru/mail/login/mailer/
2. В Supabase → Edge Functions → Secrets добавить:
   - `SMTP_HOST` = `smtp.mail.ru`
   - `SMTP_USER` = `ecolog77@inbox.ru` (или другой ящик, который разрешено использовать для отправки)
   - `SMTP_PASSWORD` = отдельный пароль приложения
   - `BOOKING_EMAIL_FROM` = тот же email отправителя
   - `BOOKING_EMAIL_SECRET` = случайная длинная строка, не менее 32 байт случайности; используется только между планировщиком и функцией.
3. В SQL Editor выполнить `supabase/migrations/003_booking_email.sql` один раз после существующих миграций.
4. Развернуть папку `supabase/functions/booking-email` как Edge Function `booking-email`. Через Supabase CLI: `supabase functions deploy booking-email --project-ref fzbhjgojsxieotjsiquv --no-verify-jwt`. В проекте функция сама проверяет секретный заголовок; публичный доступ к отправке не предоставляется. SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY доступны функции штатно; не добавляйте их в dist.
5. В Supabase Vault создать секрет `optika_booking_email_secret` с тем же значением, что у `BOOKING_EMAIL_SECRET`. Выполнить `supabase/enable-email-schedule.sql`. Раз в минуту функция обрабатывает до двух писем.
6. Открыть админку → **Email**. Указать получателя, включить уведомления, сохранить. Смена получателя НЕ меняет SMTP-пароль и отправителя.
7. С согласия владельца отправить одну тестовую заявку с заведомо тестовыми данными. Проверить запись в админке, статус письма и входящие/спам получателя. В этом задании реальные тестовые письма не отправлялись.

SMTP использует порт 465 с TLS и проверкой сертификата. Доступ к внешним приложениям должен быть разрешён в самом ящике. Пароли не присылать в чат и не хранить в репозитории.

## Если позже появится домен: Resend

Вместо SMTP можно настроить `RESEND_API_KEY` и `BOOKING_EMAIL_FROM` с подтверждённым доменом. Удалите `SMTP_PASSWORD`, чтобы переключиться на Resend. Бесплатный тестовый отправитель Resend не подходит для произвольного адреса получателя.

## Поведение

- Уведомление ставится в очередь в той же транзакции, что и новая заявка. Сеть не вызывается из формы клиента или транзакции БД.
- Старые заявки не рассылаются. Повтор той же заявки с тем же ID не добавляет второе уведомление.
- Адрес, выбранный в момент создания заявки, сохраняется в очереди. Изменение адреса применяется к новым заявкам. Неудачные письма повторяются до 6 попыток.
- Выключение приостанавливает отправку очереди; новые заявки не ставятся в очередь. Они продолжают сохраняться в панели.
- SMTP не имеет гарантии exactly-once: при обрыве после приёма письма сервером возможен повтор. Message-ID остаётся одинаковым. Для Resend применяется Idempotency-Key, автоматические повторы ограничены его 24-часовым окном.
- Статус «Принято почтовым сервером» означает приём сервисом, а не гарантированное попадание во входящие. Проверяйте спам.
- Email получателя, журнал и настройки доступны только администраторам. Пароли доступны только Edge Function. Не использовать публичную таблицу optika_content для настроек почты.
