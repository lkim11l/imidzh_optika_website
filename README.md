# Имидж Оптика — staging boutique prototype

Existing static responsive site extended in place. No framework, bundler, state library or runtime dependencies were introduced. Files in `dist/` are the published site. This project is separate from optika77.ru and CS-Cart. No production DNS, server, theme, catalog or order data is modified. All route entrypoints have `noindex,nofollow`; hosted access remains private.

## Routes and UI

- `/`: preserved hero, two editorial shopping categories, four featured models, original approach / HOYA sections, clear vision examination section, curated typographic brands, space for future real store photos, final appointment CTA.
- `/catalog`, `/catalog/optical`, `/catalog/sunglasses`: 24 products, category / gender / brand / price filters, four sort modes, active chips and reset, shareable URL state.
- `/product/:slug`: gallery with whole-image / enlarged-detail views, attributes, demo fitting request, add-to-cart, expandable service information, related products.
- `/favorites`: local saved models. `/cart`: quantity, removal, total and demo request.
- Shared search, mobile menu, filter sheet and cart drawer use native dialogs plus keyboard focus cycling and Escape handling.

Static routes are real `index.html` entrypoints generated by `node scripts/prepare-pages.mjs`. Run this after changing the homepage shell or product slugs. Lightweight client routing handles in-page transitions, Back, category and product links; refresh and direct entry do not depend on host rewrite rules.

## Data and presentation boundaries

- `dist/assets/data/products.js`: all 24 prototype records and JSDoc Product / Category / Gender / ProductImage types. Model names, attributes, prices and images are illustrative. Brands are taken from the user-provided assortment list.
- `dist/assets/data/product-repository.js`: asynchronous `ProductRepository` interface (`getProducts`, `getProduct`, `getBrands`) and client filtering / sorting. Replace its mock provider with a future CS-Cart adapter returning the same normalized Product shape. No API requests exist today.
- `dist/assets/ui/components.js`: reusable ProductCard, ProductGrid, cart and empty-state renderers. These do not import mock data and accept normalized products.
- `ProductImage` in that module and `ui/product-image.js` provide a shared square image container, accessible alt text, cached/lazy image lifecycle and neutral failure state across cards, galleries, search and cart. Failed images keep the exact allocated dimensions; native broken-image alt rendering is visually suppressed. There are no retry loops.
- `dist/assets/state/store.js`: cart / favorites browser state; versioned keys, validated records, quantity limits 1–99, cross-tab updates and fallback if persistence is blocked. No personal data is stored. These are prototype lists, not confirmed inventory or orders.
- `dist/assets/app.js`: routing and UI interaction controller. `styles.css` preserves the original visual vocabulary; `shop.css` extends it for commerce and comfortable text sizes.

## Future integration

`dist/assets/config.js` retains future verified destinations for `catalog`, `frames`, `sunglasses`, `brands`, `hoya`, `cart`, `checkout`. Current category/catalog/cart link interception can use a configured destination; null uses the working local mock routes. Other keys remain reserved for future integration. Only HTTP/HTTPS destinations are accepted. All values currently remain null. The preferred full integration is an API adapter at the repository boundary after access and requirements are confirmed.

Set `bookingUrl` to an approved booking page when available. Until then, appointment buttons open the existing clearly labelled demo. Fitting and cart requests are also explicit demos. No form data is saved or transmitted; inputs are cleared on completion/close. Do not treat submissions as appointments or requests. There is no payment or checkout integration. Actual contacts, service conditions and an approved booking integration still need to be supplied for public launch.

## Confirmed content

Operating since 2002; Moscow store; HOYA Japanese optics center; individual approach; experienced specialists; no unnecessary services; frames and lenses selection; premium brands. No invented address, phone, schedule, staff, reviews or medical claims. The catalog explicitly labels its invented model names, prices and images as prototype data.

## Asset

The original hero is preserved visually as `dist/assets/hero.webp` (77 KB instead of the 1.8 MB original PNG, which is retained). Built-in ImageGen prompt: premium editorial photograph of a single unbranded translucent smoke acetate optical frame with champagne temples on a pale icy blue seamless surface, natural daylight, gentle shadows, generous space, no text, logos or watermark, no 3D rendered look.

Three additional built-in ImageGen outputs were generated once each; exact prompts are in `ASSETS.md`. Unbranded placeholder photographs do not depict actual products from the listed brands. The two 4×3 atlases were mechanically extracted into 24 local WebP tiles in `dist/assets/products/` (191 KB combined); one editorial image is `dist/assets/sunglasses-editorial.webp`. There are no production-asset hotlinks or fabricated employee/store photographs.

The focused visual refinement adds `dist/assets/optical-lifestyle.webp` to the homepage category section. It is a fictional editorial fashion image, not a staff or customer photograph. The existing hero stays intact. Catalog cards remain packshots; the card itself is a single link with a separate favorite button and a 1.02 image hover scale. The large image-overlay pill and small new-item badges are removed. Desktop primary navigation is explicit from 1100 px; smaller viewports use the mobile menu. Each category has a compact editorial introduction and a quiet, correctly inflected model count.

## Preview

Run `node scripts/prepare-pages.mjs`, then `node scripts/preview.mjs`; local URL is http://127.0.0.1:4173. No package installation or framework build is needed. Manrope font uses the existing Google Fonts source with Arial fallback. Product images lazy-load; hero loads first; motion respects reduced-motion settings. Typography uses rem so browser text enlargement works.

`scripts/verify.cjs` exercises homepage/category navigation, 24 direct product routes, filters, sorting, search, Back, gallery, favorites/cart persistence, totals and removal, demo forms, phone validation, focus/Escape, mobile menu/filter sheet and 375 / 430 / 768 / 1024 / 1440 layouts plus enlarged text. It also checks browser errors, missing local assets and accidental production requests. Use an installed Playwright module or set `PLAYWRIGHT_MODULE` to its module path. Verification artifacts `qa-*.png` and `qa-report.json` are ignored by source publication.

`scripts/verify-refinement.cjs` additionally audits all 24 decoded images, deliberately fails image requests in a separate browser context, compares before/after dimensions in four UI contexts, verifies semantic alt retention and hidden broken-image text, checks category introductions, hover scale, desktop navigation and grids at 375 / 430 / 768 / 1024 / 1100 / 1280 / 1440 / 1920 px. The main regression suite also covers the seven requested widths through 1920 px. No framework build, TypeScript or lint commands are configured; syntax checks and static route preparation are the relevant build checks.
