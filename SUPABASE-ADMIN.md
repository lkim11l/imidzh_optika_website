## Что подключено

Товары и цены читаются из optika_products. В базе сохранены 24 исходные демонстрационные модели с прежними ID, ценами и изображениями. Показ/скрытие, цена, характеристики, флаги и фотографии редактируются в админке. Новые модели открываются через /product/?slug=… — дополнительная сборка для новой модели не нужна. Старые адреса существующих моделей работают.

Заявки на проверку зрения сохраняются в optika_bookings. Администратор видит имя, телефон, дату и статус. Статусы: новая, связались, закрыта. Успех показывается только после ответа базы. Отправка не подтверждает время визита. Почтовые и SMS-уведомления пока не подключены. Заявки на примерку из карточек и корзины остаются демонстрационными.

Раздел «Главная страница» сохраняет основные заголовки и описания в optika_content. Текст выводится как текст, без исполнения HTML. Пустые значения сохраняют исходный текст страницы.

Изображения загружаются в публичный бакет optika-products. Он предназначен только для фотографий каталога, не для документов и персональных данных. Форматы JPG/PNG/WebP, размер до 5 МБ. Сохранение фотографии и сохранение товара — отдельные операции: после загрузки нажмите «Сохранить товар». Неиспользованные загрузки можно просмотреть в Supabase Storage; автоматического удаления нет.

## Первый администратор — ещё требуется настройка учётной записи

1. В панели Supabase откройте Authentication → Users → Add user → Create new user.
2. Создайте пользователя с вашим email и паролем, который задайте самостоятельно. Вход в панель Supabase и пользователь сайта — разные учётные записи.
3. Скопируйте UUID нового пользователя. В SQL Editor выполните, заменив UUID:

   insert into public.optika_admins(user_id) values ('UUID_ПОЛЬЗОВАТЕЛЯ') on conflict do nothing;

4. Войдите на /admin/ с этим email и паролем.

Не помещайте пароль или secret/service_role ключ в исходники. Публичный publishable key в supabase-config.js предназначен для браузера. Права защищены Row Level Security в базе; произвольный зарегистрированный пользователь не получает административных прав.

Токен входа хранится только в памяти страницы, не в localStorage. Обновление страницы требует входа заново. По истечении сеанса нужно выйти и войти повторно. Параллельные изменения товаров и текстов проверяются по updated_at: вместо перезаписи чужих изменений показывается ошибка.

## Миграции и перенос

На текущем проекте уже применены 001_catalog.sql и 002_content_bookings.sql, импортирован seed.sql. Повторно запускать CREATE-миграции здесь не нужно. Для пустого отдельного проекта выполните их в порядке номеров, затем seed.sql и выдайте права первому пользователю. Не заменяйте таблицы существующего проекта без резервной копии.

Конфигурация: dist/assets/data/supabase-config.js. catalogEnabled и bookingsEnabled включены после подготовки базы. Если Supabase недоступен, каталог показывает ошибку загрузки; скрытой подмены реальных данных демонстрационными нет.

## Запуск и проверка

node scripts/preview.mjs — порт 4173. Можно задать переменную PORT, например 4174. После изменения dist/index.html запускайте node scripts/prepare-pages.mjs.

scripts/verify-admin.cjs проверяет реальное чтение каталога и UI админки с изолированными подставными ответами для операций изменения. LIVE_BOOKING_TEST=1 разрешает создание явно обозначенной тестовой заявки; обычный запуск её не отправляет. Для выбора локального сервера используйте PREVIEW_URL. Требуется доступный Playwright.

Проверено: точное совпадение всех 24 записей с исходным каталогом; реальная отправка одной синтетической заявки; запрет публичного чтения заявок и списка администраторов; запрет публичной записи товаров и текстов. Тестовая заявка «QA — тест подключения» отмечена как закрытая. Проверены сценарии создания/правки/скрытия товара, смены статуса, текстов, выхода и отказа не-администратору с подставным API. Проверка реального входа администратора и загрузки фото в Storage требует создания учётной записи. Базовые сценарии витрины и семь ширин 375–1920 px прошли проверку.

Ограничение защиты от спама: в базе есть ограничение повторной заявки с одного номера в течение 5 минут и защита от повторного сохранения одного request_id. Перед открытием формы широкой публике нужна отдельная проверка антибот-защиты. Текущий Site остаётся приватным.
